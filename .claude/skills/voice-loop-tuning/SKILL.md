# 语音回路调参与排障

板子上「能听会说」是三个独立子系统拼起来的：**采集（VAD）→ 识别（ASR）→ 播放（TTS）**，
共享同一个 codec。绝大多数「语音坏了」都是它们**互相抢资源**，而不是某一个坏了。

## 采集：麦克风前端必须先上电

直接开 ALSA 采集会失败，`snd_pcm_hw_params` 返回 **-22 (EINVAL)**。原因不是参数错，
是 **MIC 输入开关没合上**。

必须在 `hw_params` **之前**用 `snd_ctl_set` 把 MIC 输入通路打开。顺序错了照样 -22。

## 增益：单麦板子必须是 1

`CONFIG_AI_AGENT_AUDIO_CAPTURE_GAIN` 在 Kconfig 里默认是 **6**。单麦板子上这个值会让
**底噪放大 36 倍**，直接顶穿 VAD 阈值：

- 表现是**一直自己唤醒自己**，或者对着空气疯狂触发
- 你会以为是 VAD 阈值调太低，去调阈值——**调不好，因为问题在增益**

**单麦板子设成 1。** 先定增益，再调 VAD 阈值。

## DMA 争用：mic 和 speaker 抢同一条通道

**症状**：TTS 播放时报 `request dma chan failed`，或者回复断断续续。

**真因**：在只有一条 codec DMA 的板子上，**采集和播放不能同时开**。如果回复还在播的
时候去开麦克风，两边抢通道。

**修法**：在**交出控制权的那个时刻**就置忙标志，而不是等播放真正开始。具体说，
在唤醒词命中、把命令交给 LLM 的那一刻就置 `g_reply_busy = 1`，让采集线程立刻停手。
晚一步就会撞上。

**判断依据**：故障总是发生在「上一句还没播完，下一句已经开始」的边界上，而不是随机。

## codec 第二次打开无声

**症状**：第一次播放正常，**之后每一次追问都静音**，重开机又好一次。

**真因**（两处，缺一不可）：

1. `set_sysclk` 每次打开播放都无条件跑一遍
   `disable → re-parent → re-rate → enable`。**当 DAC 时钟已经在目标频率上时，这一轮
   是空操作，但它本身会把 DAC 时钟打毛。** 改成只在频率真的不同时才重配。
2. `startup` 没有清 `dapm_state`。如果某条路径在 close 之后把它留在 1，下一次
   `dapm_control(1)` 会命中提前返回，**模拟通路（DAC 使能 + 外置功放 PA）再也不会被
   重新拉起来**。在 open 时重置它。这个字段只控制那一个提前返回，重置是安全的。

**排查提示**：这类「第一次好、后面坏」的 bug，去看**驱动里那些「每次都无条件重跑一遍」
的初始化**，而不是找状态残留。

## 一句一开关 ALSA → 只有第一句出声

**症状**：回复有好几句，**只有第一句有声音**，后面的没了。

**真因**：每句都 `open → 播 → close` 一遍 ALSA。第二次 open 撞上上面那个 codec 问题，
或者撞上 DMA 争用。

**修法**：**一次回复只开关一次 ALSA。** 把整段回复按句合成，但用同一个 PCM 句柄连续写。

后来我们又把它改成流水线：起一个预取线程**提前取下一句**，主线程边播边等——首字延迟
大约减半。**但「一次 open/close」这条底线不能破**，流水线只是把取数据和播数据重叠，
不是把设备开关重叠。

## 唤醒：在 ASR 转写上做匹配

板子上没有 KWS 引擎时，「唤醒」的实际做法是：VAD 掐出一句话 → 送云端 ASR → **对转写
结果做字符串匹配**。

这带来一个必须处理的问题：**转写是不稳定的**。同一句话，空格、大小写、标点每次都可能
不同；中英混说的品牌词还可能被**音译**（`openvela` → 「欧本维拉」）。

**修法**：不要拿字面量去 `strstr`。做**归一化匹配**：

- 大小写折叠
- 把空格、标点、全角符号当**分隔符跳过**（不是删掉——原始文本要留着给 LLM，
  标点参与语义，「我不要，换一个」和「我不要换一个」不是一个意思）
- 品牌词同时准备几个**音译别名**

匹配成功后返回原文里的**起止位置**，只切掉那一段，其余原样交给 LLM。

**必须先离线单测。** 把变体（不同标点、空格、大小写、音译、以及**不该唤醒的负例**）
列成表跑一遍——这个在板子上一次一次试太慢了。附一个自查清单：

| 输入 | 期望 |
| --- | --- |
| `你好，openvela` | 唤醒，命令为空 |
| `你好 openvela 讲个故事` | 唤醒，命令 `讲个故事` |
| `Hello，OpenVela` | 唤醒 |
| `你好欧本维拉` | 唤醒 |
| `今天天气不错` | **不**唤醒 |
| `小伙伴，讲个故事` | **不**唤醒（旧唤醒词，规则已改） |

负例比正例重要——**误唤醒比喊不醒更伤体验**。别名列表每加一条，就多一个误唤醒来源，
所以要克制。

## 显示与朗读前先剥 emoji

云端 LLM 的回复里带 emoji。直接送 LCD 是**豆腐块**（字库没有），直接送 TTS 会被念成
「think」之类的怪词。

**在送显示和送 TTS 之前都要剥一遍**，不是只剥一处。

## 排障顺序

1. **没声音** → 先看是采集没上来还是播放没起来（日志里找 `-22` / `dma chan failed`）
2. **只有第一句有声音** → 一次开/关 ALSA 的底线破了，或 codec 二次打开问题
3. **追问全哑** → codec `set_sysclk` / `dapm_state`
4. **播放时采集报错** → DMA 争用，检查忙标志是不是置晚了
5. **老是自己唤醒** → 先查增益是不是 1，再查 VAD 阈值
6. **喊不醒** → 打印 ASR 原始转写，对着它调别名表
