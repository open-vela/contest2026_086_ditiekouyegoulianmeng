### 2. 多网络自动切换 🟢 v2.81 已改成 C 实现

**为什么做**：决赛现场的网络不可控，而断网 = 只剩一张困倦的脸 = 演示当场崩。
手机热点是最可靠的退路，但板子原来只会连 `/data/etc/wifi/wapi.conf` 里那一个网络。

**v2.68 的做法是错的**：候选列表写在 `/etc/wifi/start_wifi.sh` 里，在 Linux 上
用假命令跑通了 4 个场景，但真板上根本跑不起来 —— 这块板子的 `sh` 是 NSH：

- 没有位置参数（`$1/$2` 永远是空）
- 没有 `VAR=value` 赋值（每一行都被当成命令，报 `command not found`）
- 没有 `grep`（镜像里压根没这个 app）
- 不支持 `for` / `while`，循环体静默跳过

而且 NSH 的 `CONFIG_NSH_LINELEN=64`，脚本里 200 多字节的注释行会被**切成几段当命令执行**，
看起来就是一堆 `▒▒════` 开头的报错。用户实测的结果：`[wifi] 已加入:` 是空的，
最后 `wlan0` 拿了个 `10.0.0.2` 的假地址。

**v2.81 的做法**：候选逻辑全部搬进 C（`network_wifi_boot_connect()`，在
`packages/ai_agent/src/infra/network_manager.c`），脚本只剩一句提示。
开机顺序：`set_wifi` 保存的凭据 → `networks.d/0{1,2,3}.conf` → `wapi.conf` 兜底，
第一个拿到 IP 的赢，并写成新的默认。`networks.d` 由 ai_agent 开机时自己 `mkdir`。

配置一个备选网络（NSH 一条命令）：

```sh
echo '{"ssid":"手机热点","psk":"密码"}' > /data/etc/wifi/networks.d/02.conf
```

**同时修掉的两个连带问题**：

- `Found iface wlan0 addr ...` 每秒刷屏 —— 那是个查询函数每次调用都打一行，
  被自检（1 Hz）和脸谱（10 fps）轮询放大。注意**降到 `LOG_DEBUG` 没用**：
  这块板子的 `CONFIG_SYSLOG_DEFAULT_MASK=0xff`，DEBUG 一样会打出来。
  v2.81 改成**只在地址变化时打一行**。
- 运行中 `set_wifi` 之后时钟一直不校、MQTT 一直不起 —— 原来的校时和服务启动只在
  开机那 30 秒窗口里做一次。现在改成「等网络真的通了再做」，网络晚到也会自己起来。

**你需要做的**：

1. 烧 v2.81，看串口：应该**没有** `command not found` 和每秒一行的 `Found iface`
2. `ai_agent` → `set_wifi <热点名> <密码>`，等几秒，看到 `Network came up late` 就说明服务起来了
3. 重启一次，确认它自己连上、字幕板显示「可以开始」
4. **现场演示前必做**：打开手机热点，走过去重启板子，确认它自己连上了热点

### 3. 开机自检 + 字幕板报告状态 🟡 已进 v2.68，待上板验证

**为什么做**：断网或时钟不对的时候，板子表面上完全正常 —— 脸照常动、字幕照常空着，
直到小孩说了一句话没反应才发现。上台前必须有个一眼能看出来的信号。

**做了什么**：开机后每秒看一次两个状态，**结论变了就写到字幕板上**（字幕板本来就是
给旁边大人看的）；一旦测出「可以开始」自检就收工，演示过程中不再干扰字幕。

判据只用现成的两个非阻塞标志位，不新增网络请求、不碰任何控制流：

- `network_is_connected()` —— 拿到 IP 没有
- `agent_clock_is_verified()` —— 时钟校过没有（TLS 握手验过证书才算数）

**第二项是重点**：这块板子没有 RTC，**时间不对会让 HTTPS 证书的 notBefore 校验
全部失败，云端 ASR / LLM / TTS 一起哑掉，而表面上一点异常都没有**。

**你需要做的**：上板后看开机头十几秒的字幕板，对照下表。

| 字幕板显示 | 含义 | 能不能上台 |
| --- | --- | --- |
| `自检：网络通、已校时，可以开始` | 一切正常 | ✅ 能 |
| `自检：还没联网，只能看到脸` | 没连上网 | ❌ 先解决网络 |
| `自检：网络通了，但时间没校上` | 云端功能会全哑 | ❌ 先解决校时 |

**注意**：这三句话会随状态变化而更新，所以最好盯着看十几秒，而不只是瞄一眼。
最后还是那句话就说明没变过。

### 3b. 提示词静默截断（**v2.71 已修**）✅

`send_to_llm()` 里拼提示词的缓冲原来是 `MSG_BUF_LEN`（1024），但
「人设(≤308) + 孩子的话(≤1024) + 格式开销」最坏能拼出 **1352 字节** ——
编译器一路告警，超长时**静默截断**，孩子那句话从中间被砍掉且不报错。

v2.71 修掉了：缓冲改成 `PROMPT_BUF_LEN`（1024+640），并在真被截断时留一条
`prompt 被截断：需要 N 字节` 的日志。**上板时确认这条日志不该出现。**

### 14. 孩子的冒险记录 🟡 已进 v2.70，待上板验证

**做了什么**：家长端（PWA）多了一张「孩子的冒险记录」卡片。点「同步」就把板子上
角色扮演会话的文本记录取过来，按时间切成一段段冒险显示——孩子说的每句话标蓝「孩子：」，
故事正文缩进灰字。**长期档案存在手机那侧**（板子只留最近 20 条并滚动截断，
每次同步往手机上合并去重）。

**技术上有两个值得说的点**（也是这次踩到的）：

1. **MQTT 发送缓冲只有 1024 字节**，一条历史塞不下，而背靠背 `mqtt_publish` 会撞上
   `MQTT_ERROR_SEND_BUFFER_IS_FULL`。做法是切成 384 字节的小片、走 base64，
   **借已有的 sync 线程每 200ms 发一片**，不开新线程。
2. **base64 分片不能直接拼接后解码** —— 每片字节数不整除 3 时末尾带 `=` 填充，
   拼起来是错位的。实测 3621 字节的历史拼回来只剩 767 字节。正确做法是每片各自
   解码成字节再拼字节。**这个 bug 是写完之后用协议往返测试抓出来的**，
   测了「正好切断一个汉字」「空历史」「长度正好整除」三个边界。

**已经验过的**：协议往返在 Linux 上用真实中文历史跑通（7 项检查全过，单片 payload
最大 607 字节）；家长端渲染用 headless Firefox 截图确认（分组头、孩子/旁白样式都正确）。

**你需要做的**：

1. 上板后进一段冒险，讲几轮，退出
2. 手机端点「同步」
3. 看卡片上是不是出现了刚才那几轮对话，**中文有没有乱码**
4. 再点一次「同步」—— 条数**不应该翻倍**（去重生效）
5. 讲第二段冒险，再同步 —— 应该显示成**两张卡片**，而不是混在一起

**最容易出问题的地方**：中文乱码。如果看到乱码，八成是分片拼接那一环
（见上面第 2 点），把现象告诉我。

### 9d. 家庭账号后端 + 企业端 🟢 代码完成，本机验证过

**为什么做**：现在所有家庭共用一条 `kb086/out`，谁连上 broker 都能收到所有消息。
要做「每个家庭一个账号」和「企业端管所有账号」，缺的不是两个页面，是身份、隔离、归档
三件事。按你定的方案 A：**后端只做身份和路由，不存故事正文**。

**做了什么**：
- `backend/kb_server.py`：Python 标准库 + SQLite，零第三方依赖。注册/登录（PBKDF2、
  HttpOnly 会话、登录限流）、家庭与设备、设备专属 broker 账号和 topic、审计日志、
  企业端的家庭列表/停用/导出/删除。
- 每台设备一组凭据，topic 是 `kb/kb<id>/in|out`；mosquitto 用 ACL pattern 限制
  只能读写自己那一对。**本机起了 mosquitto 2.0.11 实测**：自己 in/out 收发正常，
  跨家庭 publish 被拒，用通配符订阅 `kb/+/out` 也只收到自己家的，密码错直接拒连。
- 家长端 `index.html` 加了登录闸门 + 家庭设备卡片；登录后自动带出设备参数，
  口令不再写进 localStorage。右下角「先手动连接」保留老路子，演示不依赖后端。
- 企业端 `backend/admin/admin.html`：家庭/设备/账号概览、停用、导出、删除、审计。
- 部署件：systemd、nginx 片段、`apply-broker.sh`（把设备口令写进 mosquitto）。

**刻意没做**：后端没有任何存对话的表；导出也只有账号和设备元数据。
这是方案 A 的数据边界，不是半成品。

**你需要做的**：上线要服务器 root（改 mosquitto 的 password_file/acl_file）、
一个域名和 HTTPS 证书。没有域名之前只能在局域网或演示模式里用 —— 公网明文传口令不行。
另外权限上有一处取舍：板子和手机共用同一组设备凭据，所以 ACL 是读写自己那对 topic，
没法区分「这块板子」和「这个家长的手机」。
