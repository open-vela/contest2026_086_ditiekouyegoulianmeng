# 外接呼吸灯带接线（v2.92）

板载的 WS2812（LED44）在板子中间，做氛围灯不够看，所以外接一条单色灯带。
灯带由 **PG13** 出 2 kHz PWM 推一个低边 MOS 管。平时常亮；设备在等模型
回复、或正在把故事记录回传给家长时，做 4 秒一轮的呼吸。

---

## 一、为什么是 PG13

原理图（`VELA_GEMINI_S1_R_V1.0_20260105`）里，所有 2.54 排针都对着 SoC 引脚核过一遍：

| 排针 | 引出的是什么 | 能不能做灯带 |
| --- | --- | --- |
| H1（4P） | GND / 3.3V / PB9 / PB8（I2C） | 没有 PWM |
| U10、U11（3P） | 3.3V / GND / GPADC0、GPADC1 | 模拟输入 |
| U12（3P） | UART0，和 TF 卡共用 PF2/PF4 | 不能动 |
| U27（3P） | GND / PD22(UART1_RX, 兼 PWM7) / PD21 | 中间隔一颗 BSN20，上拉 R320 是 NC，要自己补 |
| U28（3P） | UART2，调试串口 PC0/PC1 | 不能动 |
| H6（2×4） | SPI1 + **5V / 3.3V / GND** | 只有电源 |
| H4（2×4） | BT_PCM 四根信号 | **第 3 脚 = PG13** |

PG13 的功能表：

```
PG13 / I2S1_BCLK / TWI0_SDA / RGMII_CLKIN / RMII_RXER / PWM2 / LEDC_DO / UART1_RX
```

- SoC 直出，**中间没有电平转换**，3.3V 推挽；
- 有 **PWM2**，也有 LEDC_DO（后者留给 WS2812 灯带）；
- 网络名 **BT_PCM_CLK**，从 H4 第 3 脚引出来，插杜邦线就行。

代价是蓝牙 PCM 的位时钟线被占用。我们的固件只用 WiFi，不用蓝牙音频，所以没有影响。
H4 是个对插式的跳线座：**左列（1/3/5/7）接 SoC，右列（2/4/6/8）接 WiFi 模块**，
插上跳线帽两边才连通。如果 3-4 上插着跳线帽，把它拔掉，PG13 就只驱动灯带那一路。

> **别再按「第 1 脚 = PG13」接了。** 原理图第 7 页上 H4 画得很清楚，四行自上而下是
> `7 | 8 = BT_PCM_SYNC | PCM_SYNC`（PG12）、`5 | 6 = BT_PCM_DIN | PCM_DIN`（PG15）、
> `3 | 4 = BT_PCM_CLK | PCM_CLK`（**PG13**）、`1 | 2 = BT_PCM_DOUT | PCM_DOUT`（PG14）。
> 第 1 脚是 PG14，固件不驱动它，接上去量出来永远是 0.1V 左右的漏电。

**千万别动的脚**：PB6（CPU 核心电压 PWM）、PD16（BT_WAKE_AP）、PD20（屏背光）、
PG18（BT_RESETN，`/dev/gpio2` 还把它注册成了输出）。

## 二、零件

| 零件 | 规格 | 说明 |
| --- | --- | --- |
| MOS 管 | AO3400A / 2N7002 / BSS138 | 逻辑电平，Vgs(th) ≤ 1.5V；12V 灯带选 Vds ≥ 30V |
| 栅极电阻 | 100Ω | 串在 PG13 和栅极之间 |
| 下拉电阻 | 10k | 栅极到 GND，保证程序没跑起来时灯带是灭的 |
| 灯带 | 单色 5V 或 12V | 5V 可直接从 H6 取电，能带多长见下面的供电表 |

## 三、接线

```
                       5V (H6 第 7 脚) 或外部电源 +
                                 │
                          ┌──────┴──────┐
                          │   灯带 +    │
                          │   灯带 −    │
                          └──────┬──────┘
                                 │
                    漏极 D ┌─────┴─────┐
                           │   N-MOS   │
                   栅极 G ─┤           ├─ 源极 S ── GND（H6 第 8 脚）
                           └───────────┘
                              │
                   100Ω       │
   H4 第 3 脚 (PG13) ────────┘
                              │
                            10k
                              │
                             GND
```

| 板子 | 接到 |
| --- | --- |
| H4 第 3 脚（PG13） | 100Ω → MOS 栅极 G |
| MOS 源极 S | GND（H6 第 8 脚） |
| MOS 漏极 D | 灯带负极 |
| 灯带正极 | 5V（H6 第 7 脚）或外部电源正极 |
| 外部电源负极 | 板子 GND（必须共地） |
| 10k | 栅极 G ↔ GND |

> **找针**：板子上没有「PG13」丝印，找丝印 **H4** 的 2×4 排针（8 根针，
> 2.54 mm，在 WiFi 模块 BL-M8723DS1 旁边）。原理图上的针序是
> 1、3、5、7 一列，2、4、6、8 一列：
>
> | 左列（SoC 侧） | 网络 | SoC | 右列（模块侧） |
> | --- | --- | --- | --- |
> | 1 | BT_PCM_DOUT | PG14 | 2 · PCM_DOUT |
> | **3** | **BT_PCM_CLK** | **PG13 ← 用这个** | 4 · PCM_CLK |
> | 5 | BT_PCM_DIN | PG15 | 6 · PCM_DIN |
> | 7 | BT_PCM_SYNC | PG12 | 8 · PCM_SYNC |
>
> 物理上的 1 脚认方焊盘 / 丝印的「1」或圆点。**要接的是第 3 脚**：
> 和第 1 脚同一列、紧挨着的那一根（1、3、5、7 是一列），
> 不是同一排的 2 脚。接之前用万用表验一下最省事：待机时 PG13 那根有电压
> （PWM 常亮 40% ≈ 1.3V），PG14 那根是 0V 左右。

**供电**：H6 第 7 脚就是板子的 **VCC_5V**，和 SoC、屏、WiFi 共用同一条轨。
这条轨来自 DC 座（DC1，5V 输入）或者 USB-C 的 VBUS（经 SS24 二极管），
再过电源开关 SW9 和 WP3116 过压保护；整条输入通路按 **2A** 设计。
所以「有没有 5V 口」有，「是不是功率不够」要看灯带多长、以及板子从哪取电：

| 灯带（5V 单色） | 满载电流 | 怎么供 |
| --- | --- | --- |
| ≤ 30 cm，约 18 灯 | ~0.3A | 直接 H6-7，一般没问题 |
| 50 cm，约 30 灯 | ~0.5A | 用 DC 座 + 5V/2A 电源可以直接带；USB 插电脑供电不行 |
| 1 m，约 60 灯 | ~1A | 建议独立 5V 电源，共地 |
| 12V 灯带 | — | 必须独立电源，共地 |

板子自己（SoC + 屏 + WiFi + 喇叭）已经占了这条 5V 轨的大部分余量，
所以不是完全没功率，而是余量不大。固件把最高亮度压在 60%，平均电流大约只有
满载的三分之一，短灯带问题不大。判断标准：最亮时量 H6-7 对 GND，
**低于 4.7V**，或者出现板子重启 / 屏闪 / WiFi 掉线，就是余量不够，换外部电源。
5V 线上串一个 1A 自恢复保险丝、灯带端并一个 470µF 电解，能少很多麻烦。

## 四、固件做了什么

`app/kid_buddy/led_strip.c`：

1. 开机后把 PG13 复用成 **PWM2**（mux **5**，实测值），并打开下拉；
2. 直接配 PWM 通道 2 的寄存器：24 MHz 源、不分频、**2 kHz**、正常极性；
3. 起一个 4 KB 栈的线程：默认输出常亮 **40%**；只要活动位不为 0，就按
   128 点表每 31 ms 改一次占空比，曲线是 `duty = perceived^2.2`，
   4 秒一轮，最高 **60%**。开始呼吸时从「常亮那一档」接着往下走
   （v2.92），所以第一下不跳变，先暗下去再升上来；
4. 只写 `PPR2` 的 active-cycles 字段，不动周期，也不碰其他通道。

活动位目前有两个：

| 位 | 什么时候置上 | 什么时候清掉 |
| --- | --- | --- |
| `LED_STRIP_ACT_THINKING` | 孩子问完、正在等模型回复 | 回复开始播放 TTS、请求失败、或看门狗释放这一轮 |
| `LED_STRIP_ACT_BOOK` | 家长端点「同步故事书」，整批记录开始回传 | 最后一片发完，或连续失败 150 拍后放弃 |

`THINKING` 位由 `kid_buddy.c` 的脸部状态机每 100 ms 派生一次，条件就是
`g_reply_busy && g_llm_turn && !g_obs_speaking` —— 本地提示语、唤醒应答、
TTS 播放和待机都不算「思考」，灯带保持常亮。`BOOK` 位由
`ai_agent/src/channels/mqtt_channel.c` 在 `s_hist_lock` 里置/清，灯带的
实现是 weak 调用，ai_agent 单独编译时不会链接失败。

没有走 `/dev/pwmN` 的原因写在文件头：NuttX 的 PWM lower-half 每次改占空比都会
调 `hal_pwm_control()`，而它每次都会重新 pinmux；sys_config 里没有 pwm2 时会
退回硬编码的 **PE8（摄像头 OV_D5）**，等于每 20 ms 把摄像头数据脚改成 PWM 输出。
所以这里只借 HAL 打开 PWM 总线时钟，通道寄存器自己配。

### 复用号是 5，不是 6

原理图上 PG13 的功能表是
`I2S1_BCLK / TWI0_SDA / RGMII_CLKIN / RMII_RXER / PWM2 / LEDC_DO / UART1_RX`，
按「第一个复用 = 2」数下来 PWM2 是 6。用 6 配了很久，寄存器全对、计数器在跑，
H4 第 3 脚却一直是 0V，一度以为接线错了。

2026-11-04 用 v2.90 的慢扫把两个问题分开问，答案很干脆：

- PG13 当普通输出拉高 8 秒时，H4 第 3 脚**两次都出 3.3V** —— 脚位没错，
  焊盘也能驱动；
- 复用号 2~13 每档闪「N 下」，**只有 mux=5 闪了 5 下**。

所以这块 SoC 上 PG13 的 PWM2 是 **mux 5**：功能表顺序和 mux 编号不是一一
对应的，中间有一档没引出来。v2.91 把它写成默认值，并删掉了自检代码。

（更早的 v2.89 试过在串口里读 PIO 的 DAT 自动判断，12 档全是 `100%=0 0%=0`。
复用成外设功能以后，这一代的 DAT 未必还反映引脚，读回不能当证据。）

串口正常日志（v2.91）：

```
[led_strip] PG13/PWM2 2000 Hz, mux 5, steady 40%, breathe on activity (max 60%), full 10 s at boot
[led_strip] PG13/PWM2 被别人动过（复用被改，mux ret=0），已抢回（第 1 次）   ← 只在被抢时出现
```

想改亮度、周期和常亮值，改 `led_strip.c` 顶部的 `STRIP_MAX_PCT` /
`STRIP_BREATH_MS` / `STRIP_STEADY_PCT`。

## 五、上板验证

| # | 做什么 | 该看到什么 |
| --- | --- | --- |
| 5.1 | 烧 v2.91，串口 `grep led_strip` | 一行 `PG13/PWM2 2000 Hz, mux 5, ... full 10 s at boot`，没有 `复用被改成` 警告 |
| 5.2 | 不接灯带，万用表直流档量 **H4 第 3 脚对 GND** | 开机 10 秒内约 **3.3V**（全亮窗），之后稳定在约 **1.3V**（3.3V × 40%）。2026-11-04 已实测通过 |
| 5.3 | 对孩子说一句话，等模型回复 | 电压在 **0 ~ 2.0V** 之间慢慢来回（4 秒一轮，3.3V × 60% ≈ 2.0V）；回答开始播放后回到约 1.3V |
| 5.4 | 接上 MOS 管和灯带，共地 | 上电后常亮；等模型回复时 4 秒一呼一吸，最暗时完全灭、最亮约六成；TTS 开始后恢复常亮 |
| 5.5 | 板子刚上电、程序还没跑起来的那几秒 | 灯带**是灭的**（10k 下拉在起作用） |
| 5.6 | 说话、放本地提示语、唤醒 | 保持常亮（这些不是「思考」），不卡顿、不闪 |
| 5.7 | 家长端点「同步故事书」 | 整批记录回传期间呼吸；串口出现 `history: 发送完成` 后恢复常亮 |
| 5.8 | 拔掉 H4 第 3 脚 | 灯带灭；插回恢复 |
| 5.9 | **拔掉网线 / 断网后重启**，等 30 秒 | 灯带照样常亮；串口不应出现 `PG13/PWM2 被别人动过`。这一条是 v2.87 修的：之前断网启动时 WiFi/BT 那套会把 PG13 改回 PCM，灯带就再也不亮 |

**排查**：

- 待机时灯带不亮：量 **H4-3** 是不是一直为低 → 检查 PG13 有没有被别的驱动
  复用；再看串口日志有没有 `PG13 复用被改成` 和 `PG13 mux to PWM2 failed`。
  量到 **0.1V 且纹丝不动**，说明这根针上根本没有 PG13 的信号 —— 先确认线
  插在第 3 脚（1/3/5/7 是一列）。
- 断网时不亮、联网才亮（v2.87 之前）：PG13 被 WiFi/BT 的 PCM 初始化抢走。
  v2.87 起 worker 每秒抢回来一次；如果串口一直刷 `PG13/PWM2 被别人动过`，
  说明抢了又被抢，先拔掉 H4 上 1-2 的跳线帽，再看 WiFi 模块那一侧有没有
  额外拉 PCM 的配置。
- 该呼吸时不呼吸：先确认这一轮真的在等模型（联网、自检通过、串口有
  `llm ask`），而不是在放本地提示语或 TTS；同步故事书时看有没有
  `history: ... 开始发送`。
- 呼吸停不下来：看串口最后有没有 `history: 发送完成` / `放弃这一批`；
  都没有的话，等 `REPLY_BUSY_TIMEOUT_MS` 看门狗释放这一轮。
- 完全不亮：量 **H4-3** 有没有 2 kHz 波形，再量 MOS 管栅极，最后查共地。
  2026-11-04 踩过的坑是**复用号错了**：按功能表数出来是 6，写 6 时寄存器
  全对、`CNT` 在跑，脚上一直是 0V；改用 v2.90 的慢扫数出 mux=5 才出波。
  如果以后又不亮，先确认 `led_strip.c` 里 `STRIP_PWM_MUX` 还是 5。
- 亮度反相（越"呼"越暗）：把灯带正负极对调是错的，应该检查 MOS 管 D/S 有没有接反。
- 板子重启 / 灯带一闪：正常，PWM 线程会重新拉起来。
