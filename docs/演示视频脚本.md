# 演示视频脚本（≤ 5 分钟）

大赛要求：演示视频不超过 5 分钟，mp4 / mov 等常见格式。**这段视频是评委看到作品的第一
印象，`展示效果` 那 10 分基本由它决定。**

下面按时间轴给分镜。旁白能背下来最好，背不下来就用提词器——**别念稿感太重**，评委听得出。

---

## 录制前

**环境**

- 找一个安静房间。作品是云端 ASR，环境噪音会直接影响识别率。
- 光线从侧面打，别从屏幕正上方——LCD 会反光，拍出来一片白。
- 手机横屏固定住（三脚架或靠墙），**不要手持**。

**设备**

- 板子接好电源、喇叭、网线/WiFi。**先确认能联网**，不然整段视频都在等超时。
- 把屏幕右上角的版本号拍清楚——评委能确认你跑的是真机不是模拟器。

**试录**

正式录之前**先完整走一遍**，确认：
1. 喊「你好，openvela」能唤醒
2. 喇叭音量够（离手机麦克风 30–50cm 比较合适）
3. 故事能正常进入

**关键准备**：录之前**先把一个故事讲到一半**，然后放着不管，等它进入空闲状态。
第 4 段要用这个「未完成的故事」，现讲来不及。

---

## 分镜

### 第 1 段 · 开场（0:00 – 0:25）

| | |
| --- | --- |
| 画面 | 板子特写，屏幕亮着，能看清版本号 |
| 旁白 | 「这是一个跑在 openvela 上的儿童 AI 伙伴。它不只是问答——它能跟孩子一起走一段有分支的冒险故事。」 |

**要点**：25 秒内说清「是什么」。不要念技术参数，那是文档的事。

---

### 第 2 段 · 唤醒与问答（0:25 – 1:00）

| | |
| --- | --- |
| 画面 | 全景，孩子（或你）对着板子说话 |
| 台词 | 「**你好，openvela**」→ 等它应答 → 「**天为什么是蓝色的**」 |
| 旁白 | 「喊一声唤醒，之后就是普通的问答。」 |

**要注意**：唤醒词是大赛指定的，**这一段必须清楚地说出「你好，openvela」**，
让评委听到合规的唤醒词。

---

### 第 3 段 · 角色扮演与分支剧情（1:00 – 2:20）

**这是核心，给足时间。**

| | |
| --- | --- |
| 画面 | 屏幕上的对话 + 角色名 |
| 台词 | 「**我要听故事**」→ 等它开场 → 选一个角色（比如说「**故事家**」）→ 听它给出两个选项 → 说「**第一个**」 |
| 旁白 | 「它可以扮演四个不同角色。故事是有分支的——选不同的路，后面走的是不同的线。」 |

**要点**：一定要**把「给选项 → 选一个 → 剧情真的分叉了」这个来回演完整**。这是作品
最区别于普通语音助手的地方，别为了赶时间剪掉。

---

### 第 4 段 · 故事和闲聊分得开（2:20 – 3:05）

**这一段是加分项，很多同类作品做不到。**

| | |
| --- | --- |
| 画面 | 连续对话，中间插入一个无关问题 |
| 台词 | 故事进行中，问一句「**恐龙为什么会灭绝**」→ 等它回答 → 继续说「**继续讲故事**」 |
| 旁白 | 「中途问别的问题不会把剧情带跑。它把故事和闲聊分开存，回来还在原来那条线上。」 |

**要点**：回答完「恐龙」之后，**它的下一句要能接回原来的剧情**——这一点要让镜头停留
一秒，让评委看清楚它接回来了。

---

### 第 5 段 · 追问窗口（3:05 – 3:30）

| | |
| --- | --- |
| 画面 | 它刚回答完，孩子**不喊唤醒词**直接接话 |
| 台词 | 等它说完 → 直接说「**再讲一个**」（**不要**喊唤醒词） |
| 旁白 | 「刚回答完的十几秒里，孩子直接接话就行，不用再喊一遍。」 |

**要点**：旁白要说清「**这里没有喊唤醒词**」，不然评委看不出来这是个功能。

---

### 第 6 段 · 空闲主动续讲（3:30 – 4:00）

| | |
| --- | --- |
| 画面 | 板子安静地放着（用录之前准备好的那个「讲到一半」的状态） |
| 台词 | 沉默，等它自己开口 |
| 旁白 | 「孩子走开了，过一会儿它会自己接着讲——『上次的冒险讲到一半啦，还要继续吗？』」 |

**要点**：这段需要**等**。等待时间会比较长（空闲阈值），录的时候可以适当加速剪辑，
但**别剪掉它主动开口那一句**。

---

### 第 7 段 · 家长端（4:00 – 4:30）

| | |
| --- | --- |
| 画面 | 手机/电脑上的 MQTT 客户端，收到消息的一刻；或分屏：左边板子右边手机 |
| 台词 | 对孩子说「**这个故事你听懂了吗**」→ 孩子答「**我懂啦**」 |
| 旁白 | 「孩子说『我懂啦』或者『这个我不太明白』，会推一条消息到家长端。不是监控，是让家长知道今天聊到哪儿了。」 |

**要点**：把「孩子说 → 手机响」这个**因果**拍出来。只有手机截图没有说服力。

---

### 第 8 段 · 收尾（4:30 – 4:55）

| | |
| --- | --- |
| 画面 | 板子的定版镜头，或作品名 |
| 旁白 | 「代码、板级配置、预编译固件和完整的开发日志都在专属仓里。跑在一块全志 R528 的 Gemini-S1 上。」 |

**要点**：最后一句把「专属仓地址」或仓名带出来。

---

## 剪辑检查表

交之前对着过一遍：

- [ ] **总长不超过 5 分钟**（卡到 4:55 左右，别贴着上限）
- [ ] 第 2 段里「你好，openvela」听得清楚（这是规则要求）
- [ ] 第 3 段的分支选择完整演出来了
- [ ] 第 5 段明确说明了「这里没喊唤醒词」
- [ ] 第 6 段它主动开口的那句没被剪掉
- [ ] 第 7 段能看到「孩子说 → 家长端收到」的完整因果
- [ ] 版本号在某一帧里能看清（证明是真机）
- [ ] 没有把等待超时的尴尬空白留在片子里，但也别剪到看不出前因后果
- [ ] 旁白有字幕（评委可能在静音环境看）

## 容易踩的坑

- **别用「小伙伴」当唤醒词录。** 旧版本用的这个词，但大赛指定的是「你好，openvela」。
  烧新固件（v2.54），屏幕上版本号对得上再录。
- **别在视频里说「我们的 AI 模型」**。LLM / ASR / TTS 都是云端服务，作品做的是把
  它们接进一块 RTOS 板子并组织成完整体验——这是实情，也是评审要看的能力。
- **别把 5 分钟全用在念技术架构上。** 技术细节在文档里，视频是给人看「这东西用起来
  什么样」的。功能演示至少占 3 分钟。
