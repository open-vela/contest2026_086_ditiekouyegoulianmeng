# 预编译固件（kid_buddy）

本目录存放**可直接烧录的整机固件**，用于在评委环境中复现作品，无需自行编译。

| `kid_buddy_gemini-s1_uart0_128Mnand_v2.87.img.sha256` | 上者的 SHA256 校验和 |
| `kid_buddy_gemini-s1_uart0_128Mnand_v2.67.img` | 最后一次**逐项上板验证**的版本，留作回归对照 |

仓里只放**最新交付的一份**和**最后一次完整上板验证的 v2.67**，另外 v2.85、
v2.86 已经在历史提交里，留着当邻近的回退点。其余 `v2.68` ~ `v2.84` 留在本地，

### 版本变更

- `v2.87`：**灯带会自己把 PG13 抢回来。**
  - 现象：板子没连上网时灯带不亮，连上了才亮。PG13 原本是 BT_PCM_DOUT，
    WiFi/BT 那一套在开机和联网失败回退时会碰这组脚；只要有一次把复用改回去
    或把 PWM 通道关掉，灯带就再也不亮，而 worker 还在照常算占空比，屏幕上
    看不出任何异常。
  - 现在 worker 每秒重写一次 PG13 的复用、通道使能和当前占空比；发现通道
    被别人关掉会打一行 `PG13/PWM2 被别人动过`，第一次和之后每分钟一次，
    不刷屏。
  - 开机早期 GPIO 没就绪、PWM 总线时钟没起来也不再直接放弃：复用和
    `hal_pwm_init()` 各重试 5 次，全失败仍然把 worker 拉起来，运行中继续补。
  - ⚠️ 这一版**没有上板验证**。烧上去以后看串口：正常应当没有那行警告；
    如果一直刷「被别人动过」，先查 H4-1 是不是还插着 1-2 跳线帽。

- `v2.86`：**呼吸灯只在设备真的忙时呼吸。**
  - 之前灯带一上电就 4 秒一轮地呼吸，和孩子在做什么无关。现在平时常亮 40%；
    只有两个时刻呼吸：等模型回复（`LED_STRIP_ACT_THINKING`）和把故事记录
    回传给家长（`LED_STRIP_ACT_BOOK`）。
  - 「思考」不是只看 `g_reply_busy` 一个标志：本地唤醒应答、提醒、TTS 播放
    都不算。条件在脸的状态机里派生：`g_reply_busy && g_llm_turn &&
    !g_obs_speaking`，每 100 ms 同步一次。提醒、切孩子提示语和唤醒应答
    这三条本地语音路径也补上了 `g_llm_turn = 0`，免得上一轮模型对话的
    标志留着，让脸和灯带误判成还在想。
  - 故事记录回传的位由 `mqtt_channel.c` 在 `s_hist_lock` 里置/清，发完或
    连续失败放弃时清掉；灯带接口声明成 weak，ai_agent 单独编译不会链接失败。
  - ⚠️ 这一版**没有上板验证**；灯带步骤见 `docs/呼吸灯带接线.md` 第五节和
    `docs/上板验证清单.md` 第十四节。

- `v2.85`：**星芽岛有记忆了 —— 剧情里的改变会留到下一次。**
  - 之前故事的“记忆”只是最近 5 轮对话：孩子打开一个宝箱、又聊了六轮，再回头找，
    模型就不知道这个宝箱开过了。现在新增工具 `remember_world`：打开宝箱、拿走东西、
    救下谁、和居民立下约定这类**不可逆的改变**，模型当场记一条，写进
    `/data/ai_agent/kid_buddy_world.txt`。
  - kid_buddy 只在**故事模式**下把这个世界状态注入提示词（普通聊天不注入，
    “宝箱”两个字不会污染自由问答）；提示里明确写着“这些是既定事实，不要重新打开、
    不要当作没发生”。
  - 存储一行一条、FIFO 24 条、每条最多 96 字节；同一条不重复记。一个宝箱大约
    20 字，24 条足够一部长剧情。**换孩子档案目前共用一份世界状态**（和 `remember`
    的孩子档案一样），多孩子家庭需要分开的话是下一步。
  - 顺带把 `remember` 的截断修了：原来按字节硬切，正好切在汉字中间会写进半个字；
    现在退回到最后一个完整字符。拼提示词的缓冲从 4608 加到 8192，
    `poll_timer_cb` 栈用量约 14.1KB（任务栈 40KB）—— 上板时仍要 `ps` 看一眼水位。
  - ⚠️ 这一版**没有上板验证**，验证步骤见 `docs/上板验证清单.md` 第十七节。

- `v2.84`：**家长端脱离局域网。**
  - broker 从「跑在电脑上的 mosquitto」搬到公网（阿里云轻量 `123.56.1.47`）：
    板子连 `123.56.1.47:1883`，家长端网页走 `ws://123.56.1.47:8083/mqtt`，
    页面本身在 `http://123.56.1.47:8000/`。手机用 4G 也能连，家里不用再开电脑。
  - `set_mqtt` 支持一条命令设 topic 和账号密码：
    `set_mqtt <host:port> <client_id> <topic_in> <topic_out> <user> <pass>`。
  - 镜像里**不带** broker 的 topic 和密码，烧完在 NSH 里执行一次上面的命令。
    配置写在 `/data`，重启还在；重烧镜像会被 UDISK 覆盖，要再执行一次。

- `v2.83`：**故事模式多角色声线。**
  - 星芽岛的三个居民和旁白各用一种 MiMo 预置音色，孩子闭着眼睛也听得出谁在说话：
    旁白/小家伙「冰糖」（清澈少女）、守灯人阿岚「白桦」（成熟男声）、
    小狐狸栗子「苏打」（阳光少年）、圆婆婆「茉莉」（知性女声）。
  - 提示词要求模型按「阿岚：…」「旁白：…」分段；`voice_channel.c` 在分句那一步
    认出句首的名字，给这一句换音色，并把「名字：」从送去合成的文本里剪掉——
    **屏幕上和家长端故事书里仍然保留「阿岚：」**，只有 TTS 不念标签。
  - 延迟不变：本来每句就是一个独立的 TTS 请求（v2.47 的流水线），换声线只是改
    请求里的 `voice` 字段，没有多一次往返。
  - 兜底：模型某句漏标就沿用上一句的音色（默认旁白），不会报错、不会漏念。
    普通聊天不受影响（没有标签，一直是冰糖）。

- `v2.82`：**修「故事书同步下来是空白的」。**
  - 现象：孩子在故事里玩完，家长端点「同步」，手机显示「收到 3/6 片」就停住，
    再打开故事书什么也没有。串口里每一批都是 6 片里第 2、4、6 片
    `publish failed: err=-2147483632`，每失败一次就整条 MQTT 重连一次。
  - 根因在 MQTT 发送缓冲：`-2147483632` 是 `INT_MIN + 16`，即 MQTT-C 的
    `MQTT_ERROR_SEND_BUFFER_IS_FULL`。QoS1 的消息要等 PUBACK 才从队列释放，
    而 sync 线程的顺序是「先 `mqtt_sync` 把上一片发出去，紧接着发下一片」——
    PUBACK 还没回来。1 KB 缓冲装不下两片 622 字节的消息，第二片必然塞爆；
    这个错误在 MQTT-C 里是粘性的，只能靠重连清掉，重连又把已发未确认的片丢了。
  - 更致命的是发失败的那一片**当时已经推进了 offset**，等于永久丢失。
    家长端只收到 3/6，拼不齐就不导入，所以是空白而不是半截。
  - 三处一起改：发送缓冲 1024 → 2048；每片原始数据 384 → 256 字节
    （打包后约 454 字节，两片 988 字节，还留一半余量）；**发失败不推进 offset，
    下一拍重发同一片**，连续 30 秒发不出去才放弃整批并打日志。
  - 顺带修了一个隐藏的截断：原来按 UTF-8 字符边界回退，某片会变短，
    `ceil(len/片长)` 算出来的片数就少一片，最后几个字节被静默丢掉、JSON 不完整。
    家长端本来就是「每片各自解成字节再拼」，切在汉字中间没问题，回退没必要。

- `v2.81`：**WiFi 开机连接从 shell 脚本搬进 C（顺带修两个坑）。**
  - v2.68 的多网络候选列表写在 `/etc/wifi/start_wifi.sh` 里，在 Linux 上用假命令
    跑通了，**但在真板上根本跑不起来**：这块板子的 `sh` 是 NSH —— 没有位置参数、
    没有 `VAR=value` 赋值、没有 `grep`、不支持循环，而且 `CONFIG_NSH_LINELEN=64`
    会把长注释行切成几段当命令执行。板子上看到的就是一串 `command not found`，
    最后拿空 SSID 去连、拿到 `10.0.0.2` 的假地址。
  - 现在候选逻辑在 `network_wifi_boot_connect()`（`network_manager.c`）里：
    `set_wifi` 保存的凭据 → `networks.d/0{1,2,3}.conf` → `wapi.conf` 兜底，
    第一个拿到 IP 的赢并写成默认。`networks.d` 由 ai_agent 开机时自己 `mkdir`
    （NSH 没有 mkdir 命令），加备选只要一行：
    `echo '{"ssid":"热点","psk":"密码"}' > /data/etc/wifi/networks.d/02.conf`。
    `rcS.nsh` 里对脚本的调用删掉了，脚本本身只剩一句用法提示。
  - **`Found iface wlan0 addr ...` 每秒刷屏没了**：那是个纯查询函数每次调用都
    打一行，被开机自检（1 Hz）和脸谱（10 fps）轮询放大。降到 `LOG_DEBUG` 不管用
    （`CONFIG_SYSLOG_DEFAULT_MASK=0xff` 把 DEBUG 也放行了），现在改成**只在
    地址变化时打一行**。
  - **运行中 `set_wifi` 之后服务会自己起来**：原来校时和 MQTT/agent loop 只在开机
    那 30 秒窗口里启动一次，网络晚到就永远不起（实测 `set_wifi` 成功、板子能连，
    但家长端一直没反应）。现在两者都改成「等网络真的通了再做」，并打一行
    `Network came up late`。

- `v2.80`：**外接单色呼吸灯带。**
  - 板载 WS2812 在板子中间，氛围不够，这一版把灯带引到外面：**H4 第 1 脚
    （PG13 / BT_PCM_DOUT）复用成 PWM2**，2 kHz 推一个低边 MOS 管，做 4 秒一轮的呼吸
    （v2.87 起：平时常亮，只在思考 / 回传故事书时呼吸）。
    PG13 是排针上唯一一根 SoC 直出、中间没有电平转换、又带 PWM 复用功能的脚。
  - 呼吸曲线做了 gamma 2.2 校正（`duty = perceived^2.2`），最高 60%，避免低亮度段
    看着像在闪；不接灯带时这路输出悬空，不影响任何既有功能。
  - 没有走 `/dev/pwmN`：NuttX 的 PWM lower-half 每次改占空比都会重新 pinmux，
    sys_config 里没有 pwm2 时会退回硬编码的 **PE8（摄像头 OV_D5）**。所以只借 HAL
    打开 PWM 总线时钟，通道 2 的寄存器自己配。
  - 代价：蓝牙 PCM 数据线被占用（固件本来就没用蓝牙音频）；H4 上如果有 1-2 的跳线帽
    要先拔掉。接线和上板验证步骤见 `docs/呼吸灯带接线.md`。

- `v2.79`：**世界角色会主动叫孩子回来玩。**
  - 孩子在故事里说过话、然后离开 5 分钟以上，星芽岛的一个居民会主动开口
    （守灯人阿岚 / 小狐狸栗子 / 圆婆婆轮流），提一句上次冒险里的事，邀请他回来接着玩。
    这是板子主动发起的对话，不是等唤醒词。
  - 限流：两次邀请至少隔 20 分钟，一天最多 3 次。睡前时段不开口（晚上板子突然
    说话比不说话糟糕），时钟没校准或没网时也不开口。
  - 邀请那一轮发到**故事会话**，孩子接话时自动切回故事模式，剧情从上次断的地方
    接着走；如果 10 分钟内没接话，这句话仍按普通自由问答处理，不会把不相干的问题
    拽进剧情。
  - 顺带修了一个老毛病：「剧情空了一分钟要不要继续」原来每 60 秒会重复问一次，
    孩子不理就一直问；现在一个「离开」只问一次。

- `v2.78`：**把作品介绍里写了、代码里没有的四件事补上。**
  - **固定故事世界。** 故事模式追加一套固定设定：三个地点（灯塔湾 / 回声森林 /
    星星集市）、三个固定居民（守灯人阿岚 / 小狐狸栗子 / 圆婆婆）、一套世界规则
    （无死亡流血、冲突靠解谜合作、分离总会重逢、每次冒险有收束、孩子永远是主角）。
    之前是纯自由生成，地点和角色每轮都换。只加在故事模式，闲聊不受影响。
  - **情绪转介。** 之前只有输出侧敏感词过滤，孩子说「我被同学欺负了」时板子可能
    顺着聊，家长不知道。现在输入侧也过一遍词表：严重（不想活 / 被欺负 / 离家出走…）
    让这一轮先安抚、并明确告诉孩子「我会告诉爸爸妈妈」，同时推一条【重要提醒】给
    家长；一般低落（难过 / 害怕 / 孤单…）推【心情提醒】。两级分开限流，剧情里的
    「我好害怕」不算。
  - **孩子主动分享。** 故事里说「把这次冒险放进故事书 / 分享给妈妈」时，板子把这次
    冒险的会话切进独立的分享档案 `kid_buddy:share`，并告诉家长端。**家长端只同步
    分享档案**，孩子没同意分享的剧情留在板子上，不再全量上传。
  - **家长端成长日报。** 单文件网页新增「成长日报」，把分享记录和提醒回执按天汇总：
    冒险几场、说了几句、孩子说了什么、确认了哪些提醒。不调模型，每一句都能追溯到
    孩子自己的话。
  - 附带修了一个老问题：会话历史回给家长端时丢掉了 `ts`，所以之前所有冒险都被
    归成同一组。现在带时间戳，按天分组和日报才成立。
  - ⚠️ 新增的分享档案在板子上只回最近 20 条（会话模块的上限）。家长端连上会同步一次、
    孩子每次分享也会自动同步一次，档案长期存在手机上。旧版本同步过的记录没有 `ts`，
    日报里会跳过；需要的话点设置里的「清空记录」再同步一次。

- `v2.75`：**手一凑近，它就抬头看你。**
  - 板载 LTR553（光照 + 接近）在实板上确认可用：`/dev/uorb/sensor_light0` /
    `sensor_prox0`，I2C 地址 0x23、PART_ID `0x92`。实测手完全离开读 20.0，
    凑到跟前读 0.0。
  - kid_buddy 常开 `/dev/uorb/sensor_prox0`，每 200ms 非阻塞读一次；只在

  - 阈值取在驱动输出的 5 / 15 之间（20=无物体，0=很近），中间留迟滞，
    避免手停在边界时表情来回跳。
  - 这一项**不依赖网络**；节点不存在或打不开时静默跳过，不影响任何既有状态机。
  - ⚠️ 触发距离还没标定。如果只有贴上去才响应，可以调驱动里的 PS 脉冲数 /
    增益把距离拉远，但那要再烧一版。

- `v2.74`：**多孩子档案。**
  - 一个家里两个孩子时，各自的聊天记录、故事线、剧情进度各存各的 ——
    哥哥讲到一半的冒险不会被弟弟接过去继续讲。做法是把现成的会话隔离机制
    多用一层：chat_id 从 `kid_buddy` / `kid_buddy:story` 变成
    `kid_buddy:<孩子>` / `kid_buddy:<孩子>:story`，故事进度那个 flag 文件名也带上孩子。
  - 家长在 PWA 上填名字（`小明|小红`）、选当前是哪个；孩子也可以自己说
    「我是小明」来切 —— **只认列表里已有的名字、只接受短句**，
    不做模糊匹配：认错会把他的故事线换成另一个孩子的，比不认出来糟得多。
  - ⚠️ **一个档案都没配时，行为与改动前逐字一致**（chat_id 仍是原来那两个常量、
    flag 还是原来那个路径）。单孩子家庭——包括决赛演示——走的完全是老路径，
    这是这次改动最重要的约束。
  - ⚠️ **这一版动的是会话路由，也就是演示主线依赖的东西**，而且没法在板子外验证。
    上板请重点验第九节（见 `docs/上板验证清单.md`）。

- `v2.74`：**板子记住孩子说过的事。**
  - 工具表里多了一条 `remember`。孩子说到关于自己的事（最喜欢什么、养了什么宠物、
    生日、怕什么、在期待什么），模型就调一次，那句话存进
    `/data/ai_agent/kid_buddy_facts.txt`；kid_buddy 每轮把最近 6 条注入提示词，
    下次提起时它接得上。
  - **「哪句值得记」由模型判断，不由我们列规则** —— 写死的关键词表只能覆盖提前
    想到的说法。这也和整个作品一贯的做法一致：判断在模型、执行在板子。
  - 工具实现直接放在 `tool_registry.c` 里（那里本来就是内联注册工具的），
    **没有新增源文件，也没动 CMakeLists 的列表**。
  - 存储一行一条、FIFO 封顶 32 条；同一条不重复记。
  - 代价：拼提示词的缓冲再放大到 3072（最坏拼装约 2408），`poll_timer_cb` 的
    栈用量到了 **6256 字节**（任务栈 40960，占 15%）。**上板时请用 `ps` 看一眼
    kid_buddy 那行的栈高水位**，这是这一版最值得盯的一个数。

- `v2.74`：**板子会睡觉了。**
  - 到点它眼睛闭上、慢慢呼吸（睁眼量在 0~10 之间缓起缓落，约 4 秒一个来回）；
    孩子这时候说话，回答会自动切到更轻更慢的语气、讲安静的小故事，
    不再给选项、不再反问。**它不是关机** —— 睡着只是默认那张脸，
    孩子一说话、或者网络断了，其它表情立刻接管。
  - 睡觉时间默认 **21:00 → 07:00**，家长可以在 PWA 上改（两个选成一样 = 不睡）。
  - ⚠️ **时间判定只在时钟可信时才生效**（`agent_clock_is_verified()`）。
    这块板子没有 RTC，开机时是 1970 —— 不看这个标志的话它会在大白天睡觉。
    所以如果开机自检显示「时间没校上」，这个功能不会生效（这是对的）。
  - 代价说清楚：拼提示词的缓冲因此又涨了一截（多两行注入，最坏 1736 字节），
    顺手也把 `poll_timer_cb` 的栈用量顶到了 4560 字节（任务栈 40960，占 11%）。
    上板时留意一下栈水位（`ps` 看 kid_buddy 那行）。

- `v2.74`：**家长端和「归属感」四项新功能。**
  - **家长给孩子留言。** PWA 上写一句话、挑个时间（马上 / 10 分钟后 / … / 今晚 20:00），
    板子到点用 TTS 念给孩子，**原话不改写**。孩子听完说「知道了」时，回执照旧发回家长端。
    做法是把「家长从远端建的定时提醒」那条现成链路绕开大模型直接用一次：
    MQTT 通道直接排一个 cron 任务（`channel=local_client`、`chat_id=kid_buddy`，
    由 agent_loop 既有的约定决定），`delete_after_run` 保证只念一次。
    **时间只发「多少秒之后」**，由板子自己算绝对时间 —— 板子没有 RTC，
    发钟点的话时钟没校准就会念错时间，发时长则永远准。
  - **故事书导出。** 冒险记录能排成一本「孩子的冒险故事」：封面、日期范围、按时间分章，
    孩子的每句话单独标出来（蓝色 + 左侧竖线）。用浏览器自带的「打印 → 存为 PDF」导出，
    **零依赖**，手机上也能导。
  - **自由问答记录也能同步。** 复用冒险记录那套协议，只改一个 `target`
    （自由问答的 chat_id 就是 client 的 app_id `kid_buddy`）——**板子一行没改**。
  - **板子有名字了。** 孩子说「你叫小豆丁」，或家长在 PWA 上设一个；
    之后板子就用这个名字自称。语音识别做得**故意保守**（触发词都带「你」，
    把「我叫小明」「它的名字叫阿福」挡在外面），而且**当轮就让模型高兴地答应一声** ——
    认错了孩子立刻能发现，家长端那条路可以随时纠错。
  - **敏感词告警。** 内容安全过滤命中时，除了换掉那句话，还会推一条告警给家长
    （「模型刚才试图说这类话」）。5 分钟限流一次，孩子反复说同一个词不会刷屏家长手机。
  - 顺带修掉一个**一直存在的静默截断 bug**：拼给模型看的提示词缓冲是 1024 字节，
    但「人设 + 孩子的话」最坏能拼出 1352 —— 编译器一路告警，超长时孩子那句话会从中间
    被砍掉且不报错。现在缓冲给足并加了截断日志。

- `v2.70`：**孩子的冒险记录** —— 家长能看到孩子在故事里做过哪些选择。
  - 家长端（PWA）多了一张「孩子的冒险记录」卡片：点「同步」（或一连上 broker 自动同步）
    就把板子上角色扮演会话的文本记录取过来，按时间分成一段段冒险展示 ——
    孩子说的每句话用蓝色「孩子：」标出来，故事正文缩进灰字。
  - **长期档案存在手机那侧。** 板子只保留每个会话最近 20 条并滚动截断
    （`AGENT_SESSION_MAX_MSGS`），所以每次同步是把新出现的合并进手机本地，
    按 `(role, ts, content)` 去重。**板子是窗口，手机是档案。**
  - 板子侧的取数不经过 Agent：家长端发
    `{"type":"history","target":"kid_buddy:story","chat_id":"parent"}` 到 `agent/in`，
    MQTT 通道直接读会话文件回发。绕开一次 LLM 往返 —— 这是纯取数据，模型只会把它改写。
  - **传输是切片限速的，因为 MQTT 发送缓冲只有 1024 字节**（`AGENT_MQTT_BUF_SIZE`）：
    一条历史塞不下，而 `mqtt_publish` 是往缓冲里写、背靠背连发会撞上
    `MQTT_ERROR_SEND_BUFFER_IS_FULL`。做法是切成 384 字节的小片、走 base64、
    **由已有的 sync 线程每 200ms 发一片** —— 借现成的节奏限速，不开新线程。
    实测十轮冒险（3621 字节）切成 10 片，单片 payload 最大 607 字节。
  - ⚠️ 一个坑写在家长端代码注释里了：**别把各片的 base64 字符串直接拼起来再解码**。
    每片字节数不整除 3 时末尾带 `=` 填充，拼起来解码是错位的（实测 3621 字节只剩 767）。
    正确做法是每片各自解码成字节、再拼字节。协议往返在 Linux 上做过完整测试，
    含「正好切断一个汉字」「空历史」「长度正好整除」三个边界。
- `v2.69`：在 v2.68 基础上补上**可观测性**与**内容安全**两块。
  - **MQTT 出站可观测性。** 2026-09-15 出过一次「板子收得到、一条都发不出」，
    当晚重烧自愈，根因至今未明；当时最难受的是**发送失败在日志里完全看不见**——
    出站派发是单线程，被一个慢连接一卡，语音/CLI/MQTT 所有通道同时哑掉，
    而日志上一片安静。现在：`mqtt_channel_send()` 里加了成功/失败/丢弃三个计数器，
    失败日志里连 MQTT-C 自己的 `client.error` 和 `send_offset` 一起打出来；
    `mqtt_sync_thread` 里加了一条每秒看一眼的看门狗，三件事只在异常时留痕
    （错误状态变化 / 半截发送卡住 / 曾经发得出去但已静默两分钟）。
    正常情况下这三个一个字都不打，**日志里出现 `WATCHDOG` 就是现场可直接顺着查的线索**。
  - **输出侧内容安全过滤。** 报告 3.7.3 第 3 条自己承认这块「还比较基础」——
    原来只靠提示词约束，而提示词是能被绕过的。现在回复在清洗（emoji/markdown/引号）之后
    再过一道硬过滤，命中就**整段换成一句安全话，原文既不念也不显示**，并写一条告警日志。
    词表**故意做得很窄**，只收自残/自杀、性内容、毒品、危险操作指导四类；
    **有意不收泛泛的暴力词**——童话里大灰狼吃人、打怪兽都是正常情节，收了会把 RPG 主线误杀。
    误杀检查做过：16 条正常回复 0 命中。（「上床」这种一词两义的已被剔除，
    否则「该上床睡觉了」会被吞掉。）
    局限：词表目前写死在代码里，家长运行时可配需要新增 config key，这一版没做。
- `v2.68`：**决赛版第一批，两处现场保命改动。**
  - **开机连 WiFi 支持多个候选网络（⚠️ 这一版的脚本实现在真板上跑不起来，
    已在 v2.81 改成 C，见上）。** 设计是读
    `/data/etc/wifi/networks.d/0{1,2,3}.conf`，逐个试、连上就停，最后用
    `wapi.conf` 兜底。但实现写在 shell 脚本里，被 NSH 的几处限制击穿
    （位置参数、变量赋值、`grep`、循环、64 字节行宽），上板只会刷报错。
    v2.81 保留了同样的候选顺序和行为，只是搬进了 C。
  - **开机自检，结果写在字幕板上。** 每秒看一次「有没有拿到 IP」和「时钟校没校上」，
    结论变了就更新字幕：
    `自检：还没联网，只能看到脸` / `自检：网络通了，但时间没校上` /
    `自检：网络通、已校时，可以开始`。第二项是重点——这块板子没有 RTC，**时间不对
    会让 HTTPS 证书校验全部失败、云端 ASR/LLM/TTS 一起哑掉，而表面上毫无异常**，
    是最难在现场查的一类故障。测出「可以开始」后自检就收工，不再动字幕板。
- `v2.67`：字幕**改滚动**。v2.65/v2.66 的正文只显示两行，后面直接省略号截掉——
  而提示词要求模型答 100 字，两行 33 格只有 66 格，**大部分回复都断在半句，剩下的
  够不着**。改成：正文标签可以长到 8 行，前面开一个正好两行高的窗口，
  每 2.5 秒往上走一行，走到底再回到开头循环。孩子那句话的那一行不动。
  窗口是一个普通对象，LVGL 只按矩形裁剪子对象（`lv_refr.c` 里按父对象坐标取交集），
  所以窗口外的行是真的没画，不是被压扁。正文没变化 2.5 秒后才开始走，
  流式回复不会一边滚一边改字。
- `v2.66`：修字幕**换行**（v2.65 的字幕在模型回复里带换行时会溢出到第三行，
  多出来的那一行被标签裁掉，正文会**无声地断在半句**，连省略号都没有）。
  换行改由应用自己算：按字体实际宽度精确计格（8px 半角 / 16px 全角，并单独列出
  SimSun 里 128 个"小于 U+2000 但其实是全角"的字符 —— ° ± × ÷ 希腊字母、
  西里尔字母，这些按半角算会让一行宽 8px，恰好够 LVGL 再折一次行），
  逐字断行并写入 `\n`，超出两行的部分以省略号结尾。
  顺带修了孩子那一行被重复扣掉 4 格（「你：」前缀被算了两遍）。
- `v2.65`：**脸谱下方加回字幕** —— 底部三分之一是一块三行字幕板：第一行是
  孩子说的话（「你：」+ 语音识别结果），下面两行是模型回复正文。
  脸等比缩到上面三分之二，六个表情与全部道具照旧。
  字幕正文是为了**评委和旁观的大人**——孩子自己读不了，但语音链路一旦没出声，
  屏幕上的字是唯一能证明"它在工作"的东西。刷新做了节流（流式回复最快 250ms 一次，
  最终一定刷），避免每来一小段就刷一整屏、跟 TTS 抢 SPI。

- `v2.63`：修首次开机屏幕上出现 `Sorry, I encountered an error.` 的问题 —— 没联网时
