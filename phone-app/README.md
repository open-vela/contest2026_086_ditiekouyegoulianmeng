# 家长端控制台（phone-app）

家长在手机上用的一个网页，**可以装到主屏幕当 App 用**。用它给板子发消息、设提醒，
并看板子回来的回复和回执。

和板子之间走 **MQTT**：板子用 1883 明文 TCP 连 broker，这个页面走 **WebSocket**。
broker 已经放到公网（阿里云轻量应用服务器），**不需要家里再开一台电脑**：

| 谁 | 连哪 |
| --- | --- |
| 板子 | `123.56.1.47:1883`，topic `kb086/in`（收）/ `kb086/out`（发） |
| 这个页面 | `ws://123.56.1.47:8083/mqtt`，topic 同上 |
| 页面本身 | `http://123.56.1.47:8000/` |

用户名 `kidbuddy`，密码见队内记录（仓库里不写）。broker 上还有 ACL，
这个账号只能读写这两个 topic。

> 上面是**手动连接（演示）模式**。接了家庭账号之后，正常路径是登录后由后端下发
> 每台设备自己的 broker 账号和 topic（`kb/kb<设备id>/in|out`），不再共用 `kb086`。
> 见下面「家庭账号」。

## 家庭账号（可选）

账号服务在 [../backend/](../backend/)，只做身份和路由，**不存故事正文**。

- 页面打开时会问 `/api/me`：登录了就自动带出上次那台设备的连接参数（口令每次
  从后端取，**不再写进 localStorage**）；没登录就弹登录框。
- 登录框右下角有「先手动连接」，点掉就回到老路子 —— 后端没部署、断网、或者比赛
  现场不想依赖账号服务时都走这条。
- 登录后在「家庭账号」卡片里添加板子，会生成一条 `set_mqtt …` 命令。在板子
  串口先敲 `ai_agent` 进它自己的 CLI（提示符 `vela>`），再把命令粘进去，
  板子就会用这个家庭专属的 topic 连上来。命令在 `nsh>` 下会报 not found，
  而且 NSH 行宽只有 64 字符。
- 换密码 / 删除设备也在这张卡片里。换密码后板子要重新执行一次新命令。

页面和 `/api` **必须同源**才能自动登录（后端托管页面或 nginx 反代都行）。
本地可以把后端当静态服务器直接起：

```bash
cd backend
python3 kb_server.py --init
python3 kb_server.py --create-admin you@example.com '至少八位口令' --family 运营
KB_HOST=0.0.0.0 KB_PORT=8080 python3 kb_server.py --serve
# 手机打开 http://<电脑局域网IP>:8080/ ，企业端是 /admin/
```

普通的收发消息走的是 ai_agent 原有的格式，**板子一行没改**；后来加的「冒险记录 /
留言 / 起名字」用了几种新的消息 `type`，那部分板子上有对应的处理（见下面各节）。

## 文件

| 文件 | 作用 |
| --- | --- |
| `index.html` | 页面本体（界面 + MQTT + 本机存储），**要改就改这个** |
| `manifest.json` | PWA 清单：名字、图标、独立窗口 |
| `service-worker.js` | 离线外壳，缓存页面本身。**改了 index.html 记得把里面的 `CACHE` 版本号 +1** |
| `mqtt.min.js` | mqtt.js 5.x，**已本地化**，不再依赖 CDN，离线也能开 |
| `icons/` | 图标，画的是一张几何脸（跟板子上那张同源） |

## 怎么起

**平时用**：手机直接打开 `http://123.56.1.47:8000/`，页面和 broker 都在那台阿里云
服务器上，家里不需要开电脑。

**改完页面要更新**：把 `phone-app/` 传到服务器的 `/srv/kid-buddy/phone-app/`，
nginx 直接生效（传之前记得把 `service-worker.js` 的 `CACHE` 版本号 +1）。

**本地调试**：直接双击 `index.html`（`file://`）不行，浏览器会拦住 service worker
和 IndexedDB。在放着 `phone-app/` 的目录下起一个静态服务器：

```bash
python3 -m http.server 8000        # 或 Windows 上：python -m http.server 8000
```

然后手机浏览器打开 `http://<这台机器的局域网IP>:8000/phone-app/`。

## 怎么装到手机

**安卓（Chrome / Edge）**：右上角菜单 → 「安装应用」或「添加到主屏幕」

**iOS（Safari）**：底部分享 → 「添加到主屏幕」

装完就是一个独立图标，点开全屏、没有地址栏。

## ⚠️ http 和 https 的区别（这个必须知道）

页面用 `http://`（不管是局域网 IP 还是公网 IP）打开时，**浏览器不给注册
service worker**（不是安全上下文）。具体差别：

| 能力 | `http://` | `https://` |
| --- | --- | --- |
| 打开、连 MQTT、收发消息 | ✅ | ✅ |
| 数据存本机、重开还在（IndexedDB） | ✅ | ✅ |
| 装到主屏幕、有图标 | ✅（快捷方式） | ✅（独立窗口） |
| 离线能打开（service worker） | ❌ | ✅ |

**做演示够用** —— 核心功能一样不缺，只是离线缓存那条不生效。

⚠️ 还有一条：**https 页面不能连 `ws://`**（浏览器当混合内容拦掉）。所以哪天真要上
https，broker 那边得同时配 `wss://`。

## 本机存了什么

| 数据 | 存在哪 | 容量 |
| --- | --- | --- |
| Broker 地址、chat_id、topic、用户名 | `localStorage` | 5–10MB |
| 和板子的收发记录（最近 200 条回显） | **`IndexedDB`**（`messages`） | 按几百 MB 算 |
| **孩子的冒险记录** | **`IndexedDB`**（`story`） | 同上 |

- **密码两边都不存**，每次连接手输。
- 只存 `in`（板子→手机）和 `out`（手机→板子）两类，连接/重连提示那种刷屏的不存。
- 设置页里能看到「本机记录：N 条」，旁边有「清空记录」。

## 孩子分享的冒险

页面上有一张「孩子分享的冒险」卡片。点「同步」（或者连上 broker 后自动同步一次、
孩子在板子上说「把这次冒险放进故事书」时也会自动同步），它会把板子上的
**分享档案**取过来，按时间切成一段段「冒险」显示：孩子说的每句话前面标蓝色的
「孩子：」，故事正文按原来的先后顺序跟在后面。

**为什么不是全量记录**：故事会话 `kid_buddy:story` 只留在板子上给孩子续讲，
家长端同步的是 `kid_buddy:share`。孩子在故事里明确说「放进故事书 / 分享给妈妈」
时，板子才把这次冒险切进分享档案。所以网页想多要，也拿不到没分享的剧情 ——
闸门在板子上，不靠网页自觉。

**这一块的数据长期存在手机上，不是板子上。** 板子每个会话只留最近 20 条、会滚动截断，
所以每次同步是把新出现的**合并**进本机，按 `(role, ts, content)` 去重 ——
同步多少次都不会重复，板子记不住的历史手机上还留着。

**它是怎么走的**：往 `agent/in` 发一条

```json
{"type":"history","target":"kid_buddy:share","chat_id":"parent"}
```

板子的 MQTT 通道收到后直接读会话文件，**不经过大模型**（这是纯取数据，
绕一次 LLM 又慢又会被模型改写），然后切片回发：

```json
{"type":"story_log","chat_id":"parent","target":"kid_buddy:share",
 "seq":3,"total":10,"data":"<base64 片段>"}
```

`seq` 从 1 开始，`total` 是总片数；收齐了才拼装解析。故事记录的切片**不进对话日志**，
状态显示在卡片标题栏（「收到 3/10 片」→「本机共 N 条」）。

> ⚠️ **改这块代码的人注意**：不要把各片的 `data` 字符串直接拼起来再解码。
> 每片的字节数不一定整除 3，base64 末尾会带 `=` 填充，拼起来解码是错位的
> （实测 3621 字节的历史只剩 767 字节活下来）。正确做法是**每片各自 `atob` 成字节、
> 把字节拼起来**，最后整体做一次 UTF-8 解码 —— 见 `partsToUtf8()`。

## 成长日报

下面还有一张「成长日报」卡片。它不调模型，只把本机已有的两份数据按天聚合：

- 分享记录里的冒险场次、孩子说的话；
- 板子推回来的提醒确认回执（`孩子已确认提醒：…`）。

每天一行，最近 7 天。孩子怎么说就怎么记，不会出现「今天心情很好」这类模型总结。
旧版本同步进来的记录没有 `ts`，会被跳过；需要的话点设置里的「清空记录」再同步一次。

## 给孩子留言 / 故事书 / 给板子起名字

除了「收发消息」和「冒险记录」，这张卡片上还有三件事：

**给孩子留句话** —— 写一句、选个时间（马上 / 10 分钟后 / … / 今晚 20:00），
板子到点用语音念给孩子，**原话不改写**（板子那边走的是不含大模型的路，
不会像普通提问那样被模型重写一遍）。孩子听完说「知道了」，回执照旧发回来。

> 时间只发「多少秒之后」，绝对时间由板子自己算 —— 板子没有 RTC，
> 发钟点的话时钟没校准就会念错时间，发时长则永远准。

**故事书** —— 把冒险记录排成一本「孩子的冒险故事」：封面、日期范围、按时间分章。
正文和孩子的台词用同一套字体，按「一句一行」排，孩子那几行只多一个「孩子：」前缀，
读起来是一段连续的故事、不是两份材料。点「打印 / 存成 PDF」用浏览器自带的导出，
**不依赖任何库**，手机上也能导。

**板子的名字** —— 填一个点「设名字」。孩子自己说「你叫小豆丁」也能设（板子上做了
一套保守的语音识别），但语音认名字不靠谱，这里是可靠的那条路，用来兜底和纠错。

协议分别是：

```json
{"type":"note","content":"…","from":"妈妈","delay":600,"chat_id":"parent"}
{"type":"petname","name":"小豆丁","chat_id":"parent"}
```

`delay` 是秒数（0 = 马上）。自由问答的记录用同一条记录协议、换个 target 就行：
`{"type":"history","target":"kid_buddy","chat_id":"parent"}` ——
自由问答的 chat_id 就是板子 client 的 app_id `kid_buddy`。

## 怎么用

1. 在 broker 上开 WebSocket listener。以 mosquitto 为例，在 `mosquitto.conf` 里加：

   ```
   listener 9001
   protocol websockets
   ```

2. 手机和 broker 在同一个局域网（或 broker 在公网）时，手机浏览器打开上一步的地址。

3. 页面上填：

   | 字段 | 说明 | 默认 |
   | --- | --- | --- |
   | Broker 地址（WebSocket） | 形如 `ws://192.168.1.100:9001` | 空 |
   | 我的 chat_id | 家长自己的会话标识，回执按它匹配 | `parent` |
   | 发送 topic（→板子） | 板子的入站 topic | `agent/in` |
   | 接收 topic（板子→） | 板子的出站 topic | `agent/out` |
   | 用户名 / 密码 | broker 要求认证时填，否则留空 | 空 |

   填过的设置存在浏览器里，下次打开还在。**密码不存**。

4. 点「连接」，状态灯变绿后就可以发消息了。

## 界面

- 底部四个快捷按钮：提醒喝水 / 提醒睡觉 / 打个招呼 / 看孩子回执
- 也可以直接在输入框里打任意一句话发给板子
- 上方日志区显示收发内容。板子回来的消息标「📥」，带 chat_id 的一并显示

## 消息格式

发给板子（`agent/in`）：

```json
{"type":"message","content":"提醒孩子 30 秒后喝水","chat_id":"parent"}
```

从板子收（`agent/out`）：

```json
{"type":"response","content":"……","chat_id":"parent"}
```

## 验证到什么程度

**全链路已跑通**（家长端 → 板子 → 家长端，再到点播报）：
从网页发「提醒孩子…喝水」→ 板子记住这条任务 → 板子回一条确认消息到网页 →
到设定时间板子开口语音提醒喝水。四个环节都实际走过。

另外，孩子听完提醒后说「知道了」触发的那条**儿童确认回执**（经 `agent/out` 发回、
按 chat_id 区分）在板子侧单独上板验证过。

**PWA 部分**：用 headless Firefox 在 `http://localhost` 下实测过 —— 页面正常渲染、
service worker 成功注册（服务器日志里能看到 `GET /service-worker.js`）、
IndexedDB 打开成功（日志区那句开场白是在 IndexedDB 回调里打出来的）。

## 注意

- 板子侧的 MQTT 通道默认是**关**的，需要在板级配置里同时打开
  `CONFIG_AI_AGENT_MQTT` 和 `CONFIG_NETUTILS_MQTTC`，并且删掉对应的 `.o` 强制重编，
  详见仓库根目录 README 的板级改动一节。
- 这个页面走的是**明文 ws://**。放公网用的话，需要给 broker 配 TLS 并把地址换成
  `wss://`，这一版没做。
